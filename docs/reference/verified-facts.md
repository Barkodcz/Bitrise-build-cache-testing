| Bundler silently recompiles native extensions across a Ruby ABI-version mismatch, rather than failing | `RB-B02` (seed Ruby 3.2.2, measure Ruby 3.3.0, same OS, same cache key) restored with `restore_hit=exact`, and the subsequent smoke test passed on the first try with no visible error — but the `bundle install + smoke test` step took **2.7 minutes**, vs. ~13 seconds for the equivalent step in `RB-G01`/`RB-B01` on the same machine class. RubyGems/Bundler install compiled extensions under an ABI-version-specific path (`extensions/<platform>/<ruby-abi-version>/...`); restoring a cache built under a different Ruby version doesn't crash anything, it just means Bundler doesn't find a matching extension directory and quietly recompiles from scratch. The symptom is wasted *time* with zero visible error, not a build failure — a quieter, easy-to-miss version of the same underlying "toolchain version belongs in the cache key" lesson as `GO-B02`/`RS-B02`. | 2026-11-26 | Real `showcase-ruby` pipeline run on app `84c7a274-43b0-477d-9141-ea174ad0ce6e` (build 27, `rb-b02__2_measure` `57cf234b-663e-4a68-8db2-223a66f19e6b`). |

Confirmed via a temporary diagnostic `cat` of that file (build 30, `ios-g01__2_measure`), which showed a real line: `Proxy blob stats: hits: 252 (103 MB) / total: 254 (99.21%). Uploaded blobs: 22 (280 kB)`.
