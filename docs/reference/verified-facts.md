| Gradle init-script `BuildService` + `BuildEventsListenerRegistry` lifecycle | The `Provider<T>.get()` you call later (e.g. inside a `gradle.buildFinished {}` callback) is **not guaranteed to return the same instance** that `BuildEventsListenerRegistry.onTaskCompletion()` fed `onFinish()` events to — confirmed empirically via `System.identityHashCode()` logging (two different instances across `onFinish` vs. a later `provider.get()`). Fixed by making the service implement `AutoCloseable`/override `close()` (which Gradle calls on the exact instance that received the events) and writing the report there instead of from a `buildFinished` callback. See `tools/metrics/gradle/showcase-metrics.init.gradle.kts`. Also: `BuildEventsListenerRegistry` must be fetched from `(gradle as GradleInternal).services`, not from a `Project`'s service registry — a project-scoped lookup only observes that one project's own task events, not the whole build's. | 2026-11-26 | Live `./gradlew :app:assembleDebug :core:model:testDebugUnitTest --init-script tools/metrics/gradle/showcase-metrics.init.gradle.kts` against `projects/android`, with temporary debug logging to isolate the bug, then re-verified clean after the fix: `gradle.json` fragment correctly reported `executed=10, from_cache=6, up_to_date=6`, matching an independent `grep -c FROM-CACHE` cross-check of the raw build log (6). |
